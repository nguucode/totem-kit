# Typography

Type is **role-based**, following the [Atlassian Design
System](https://atlassian.design/foundations/typography) scale: you pick
`text-heading-lg` or `text-body`, not a size. Each role carries its size,
line height and weight together, so a heading cannot accidentally be set
at body weight or a body line height.

That is the one structural difference from Tailwind's default type scale,
which is purely dimensional — `text-2xl` says how big, never what it is
for. Both are available; the roles are what components use.

## The typeface

`--font-sans` leads with **`system-ui`**:

```css
system-ui, -apple-system, 'Segoe UI', Roboto, 'Helvetica Neue', Arial,
sans-serif, 'Apple Color Emoji', 'Segoe UI Emoji'
```

This is deliberately *not* Tailwind's default stack, which starts at
`-apple-system` and omits `system-ui` entirely. `system-ui` is the
standards-track keyword and resolves to the platform's **UI** face — San
Francisco on Apple platforms, Segoe UI Variable on Windows, Roboto on
Android — which is the face those platforms' own controls use. Everything
after it is a fallback for browsers that do not support the keyword.

<Canvas of={TypographyStories.Families} />

**The known caveat.** Tailwind omits `system-ui` because on some Linux and
older Android configurations the keyword resolves through fontconfig to
whatever is aliased as the system font, which has historically produced a
serif or a missing-glyph fallback for non-Latin text. The fallbacks after
it do not help, because the keyword *did* resolve — just badly. If you
ship to those platforms and see the wrong face, drop `system-ui` from the
front of the stack; everything else in the kit is unaffected.

Nothing is downloaded, so the kit renders in a different face on every
platform by design. That is the right default for product UI and the wrong
one for a brand with its own type — see **Customization** below.

## Headings

Seven steps, all bold. The line height tightens as the size grows, which
is the part a purely dimensional scale gets wrong when it applies one
ratio everywhere.

<Canvas of={TypographyStories.Headings} />

| Role | Size | Line height | Atlassian |
| --- | --- | --- | --- |
| `text-heading-2xl` | 2rem / 32px | 36px | `font.heading.xxlarge` |
| `text-heading-xl` | 1.75rem / 28px | 32px | `font.heading.xlarge` |
| `text-heading-lg` | 1.5rem / 24px | 28px | `font.heading.large` |
| `text-heading-md` | 1.25rem / 20px | 24px | `font.heading.medium` |
| `text-heading-sm` | 1rem / 16px | 20px | `font.heading.small` |
| `text-heading-xs` | 0.875rem / 14px | 20px | `font.heading.xsmall` |
| `text-heading-2xs` | 0.75rem / 12px | 16px | `font.heading.xxsmall` |

The suffixes are Tailwind's (`2xl` … `2xs`) rather than Atlassian's
(`xxlarge` … `xxsmall`) so they read the same way as every other size in
the kit. The mapping above is one to one.

Note that headings go *below* body size: `text-heading-2xs` is 12px. Those
bottom steps are for labels and section eyebrows — a heading role is about
the semantic weight of the text, not about being large.

## Body

Three steps. `text-body` is the default at 14px, which is Atlassian's
default and one step down from the 16px most Tailwind projects start at.

<Canvas of={TypographyStories.Body} />

| Role | Size | Line height | Atlassian |
| --- | --- | --- | --- |
| `text-body-lg` | 1rem / 16px | 24px | `font.body.large` |
| `text-body` | 0.875rem / 14px | 20px | `font.body` |
| `text-body-sm` | 0.75rem / 12px | 16px | `font.body.small` |

**Every component uses these.** Button, the field label, the input itself,
and the helper and error text are all `text-body`; only the large Button
steps up to `text-body-lg`.

## Weights

Four, matching Atlassian's set. Tailwind defines nine; the other five are
not part of this system.

<Canvas of={TypographyStories.Weights} />

| Utility | Value | Atlassian |
| --- | --- | --- |
| `font-normal` | 400 | regular |
| `font-medium` | 500 | medium |
| `font-semibold` | 600 | bold (body) |
| `font-bold` | 700 | bold (heading) |

**A weight utility always beats the role.** Tailwind emits the role's
weight as `font-weight: var(--tw-font-weight, 700)`, and `font-*` sets
`--tw-font-weight` — so the role's value is a fallback, not a rule, and
overriding it does not depend on class order. That is why Button can be
`text-body font-medium` without the 400 in `text-body` fighting it.

With a system stack, the weight you ask for is not guaranteed to be a
drawn face: where one is missing the browser synthesises it, and
synthesised weights look noticeably worse. 400 and 500 are safe
everywhere; verify 600 on the platforms you support.

## Scaling

Every size above is `calc(<base> * var(--scaling))`, so the
[`scaling`](?path=/docs/foundations-overview--docs) setting moves type and
spacing together. Line heights are stored as *ratios* of Atlassian's px
pairs — `calc(20 / 14)` rather than `1.25rem` — so they follow the font
size instead of having to be rescaled themselves.

## What is not here

**Metric tokens.** Atlassian has `font.metric.*` for large figures. Their
sizes are identical to three of the heading steps; the real difference is
tabular figures, which Tailwind already covers with `tabular-nums`. There
is no stat component yet, so the role would be three tokens nothing reads.

**`font.code`.** Same size as `text-body-sm`, differing only by family.
`font-mono` covers it until a Code component exists.

**The raw scale.** `text-xs` through `text-6xl` still exist and still
scale — they are Tailwind's and removing them would break expectations.
Prefer a role in component code; reach for the raw scale for one-off
display type that no role describes.

## Customization

The family is a theme key like any other:

```css
@theme {
  --font-sans: 'Inter Variable', system-ui, sans-serif;
}
```

Every `font-sans` utility and the default body text pick it up with no
component change. Re-check the weights when you do — a real typeface
usually ships fewer weights than the four above, or different ones.

To move the scale itself rather than the face, override the role tokens
directly; each is `--text-<role>` plus its `--line-height` and
`--font-weight` companions.
